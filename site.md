# Cui Bono? — сайт, Дзен и конвейер публикации

Состояние на 1 ноября 2026. Что нужно знать, чтобы работать с каналом, сайтом и Дзеном в новой сессии. Правила текстов — в «Единой системе» (`system.md`) и «Telegram» (`telegram.md`); здесь только устройство площадок и как они связаны.

## Три площадки и как они связаны

| Площадка | Что там | Откуда берётся |
| --- | --- | --- |
| Telegram @cuibono_press | Главная витрина: заметки, разборы (анонс + кнопка), позиции, показатели, неделя | Бот публикует по расписанию |
| Сайт cuibono.press | Каждый текст отдельной страницей, разборы целиком, страницы рубрик, тем и данных | Бот собирает после каждой публикации и выкладывает на Cloudflare Pages |
| Дзен | Статьи канала Дзена | Дзен сам забирает ленту `cuibono.press/zen.xml` (после одобрения ленты; до этого — синхронизация из Telegram через @zen_sync_bot) |

Связи: пост в канале → страница на сайте (ссылка «Этот текст в канале» на посте) → лента для Дзена → в конце статьи в Дзене «Оригинал — cuibono.press. Cui Bono? в Telegram». Кнопка разбора в канале ведёт на сайт. Сайт везде ведёт в канал.

## Где что лежит

- **Бот:** приватный репозиторий github.com/Unzeabk/cui-bot, работает в GitHub Actions.
- **Код сайта:** `bot/site.py` (страницы, SEO, лента Дзена), `bot/data_pages.py` (страницы данных).
- **Данные сайта:** `state/site-posts.json` — все тексты сайта. Журнал ленты для правил чередования — `state/posted.json` (хранит 7 дней).
- **Собранный сайт:** папка `site/` в репозитории; выкладывается на Cloudflare Pages, проект `cuibono`. Публичного репозитория нет: имя владельца на GitHub нигде не светится.
- **Домен:** cuibono.press, DNS и хостинг — Cloudflare.
- **Ключи:** секрет `CLOUDFLARE_API_TOKEN` в GitHub; Account ID Cloudflare, номер Яндекс.Метрики (113988036), код подтверждения Дзена прописаны в коде и workflow.

## Расписание (МСК)

| Что | Когда |

| Заметка | 6 в сутки: 08:37, 10:37, 12:37, 17:07, 19:37, 22:07 |
| Разбор | каждый день 11:22, запасной 15:22 (пропускается, если утренний вышел) |
| Позиция | каждый день 13:52 и 20:52 |
| Показатели | пн 10:52 |
| Неделя | сб 12:52 |

Рубрика у задачи «рубрики» выбирается по расписанию, которое её запустило (`CRON`: 52 7 — показатели, 52 9 — неделя, 52 10 и 52 17 — позиция, 22 8 и 22 12 — разбор), а не по часу: GitHub часто запускает с опозданием. Квота: сильной модели ~20 запросов в сутки; 6 заметок ≈ 6, разбор ≈ 7, две позиции ≈ 2–4. Темы не повторяются: отбор отсекает всё, о чём уже писали за неделю, включая позиции.

## Конвейер

- **Заметка, позиция, неделя:** текст → проверка кодом и фактчек → обложка → пост в Telegram → отдельный лёгкий запрос даёт SEO-заголовок, описание и темы → запись для сайта → журнал ленты → сборка сайта → выкладка на Cloudflare → через минуту адрес уходит в Яндекс и Bing (IndexNow).
- **Разбор:** план из пяти частей и части по отдельности (только сильная модель; нет квоты — переносится) → проверка → обложка → **сначала сайт** (запись, сборка, выкладка, 20 секунд ожидания) → пост в Telegram с кнопкой на cuibono.press → повторная сборка с номером поста. Если сайт не выложился — запасной путь telegra.ph.
- **Показатели:** табло ЦБ и Мосбиржи только в Telegram; на сайте цифры живут на страницах данных.
- Ошибка сайта, SEO-запроса или источника данных никогда не мешает посту в канале.

## Сайт

- **Адреса:** `/p/<дата>-<slug>` текст, `/r/<рубрика>`, `/t/<тема>`, `/a/<год-месяц>` архив, `/data/...` данные, `/about`, `/archive`, `/sitemap.xml`, `/feed.xml`, `/zen.xml`.
- **Оформление:** тёмный фон и шрифты брендбука; обложка на странице не показывается (повторяет заголовок), но стоит в og:image и разметке для поиска и превью. Стили версионируются (`style.css?v=…`), чтобы браузер не держал старые.
- **SEO:** у страницы свой заголовок для поиска (поле `seo_title`, пишет лёгкая модель после публикации; в канале заголовок прежний), описание, canonical, Open Graph, разметка NewsArticle, хлебные крошки; страницы тем (в индекс — от трёх текстов), «По теме» по общим темам, первые упоминания тем — ссылки; тексты короче 350 знаков закрыты от индекса; IndexNow; Яндекс.Метрика с целью «переход в Telegram».
- **Страницы данных:** ключевая ставка (вся история решений), курсы доллара, евро, юаня ЦБ, индекс Мосбиржи, золото. Обновляются при каждой сборке из первоисточников; если источник молчит, остаётся прошлая версия.
- **«Об издании»:** две строки, без объяснений метода (недосказанность).
- Тексты, вышедшие до 1 ноября, бот не сохранял; владелец 1 ноября очистил сайт, дальше он наполняется с нуля.

## Как управлять сайтом

- **Убрать текст:** вписать адрес страницы или номер поста в `state/site-remove.txt` и закоммитить — сайт пересоберётся сам.
- **Пересобрать вручную:** Actions → «Cui Bono — сайт» → Run workflow. Галочка «Удалить все тексты» очищает сайт полностью — использовать осторожно.
- **Правка `state/site-posts.json` руками** сама сборку не запускает: после неё — Run workflow.
- Ручные правки в `site/*.html` бессмысленны: сборка перерисовывает всё. Любое изменение сайта — в коде бота.

## Дзен

- Канал в Дзене есть, 10 подписчиков набрано 1 ноября. Домен подтверждён мета-тегом.
- **Лента** `cuibono.press/zen.xml` собрана по «Техническим требованиям к RSS-ленте» Дзена: `contentType` blogs_only (статьи для канала), рубрика сайта, index, comment-all, только материалы за 7 дней, заголовок без точки, обложка через enclosure, пространства имён как в образце Дзена (https). В конце статьи — «Оригинал — cuibono.press. Cui Bono? в Telegram».
- **Подавать ленту**, когда в ней не меньше 10 статей (Студия → Настройки → Свой сайт / Новости → Экспорт). Попыток — 3 в год, после третьего отказа блок на 12 месяцев. После одобрения отключить синхронизацию Дзена с Telegram, иначе дубли.
- Синхронизация из Telegram через @zen_sync_bot делает заголовком первое предложение поста, поэтому позиции выглядят криво («ПОЗИЦИЯ · Мнение редакции»), а разборы не переносятся. Это временно, до ленты.
